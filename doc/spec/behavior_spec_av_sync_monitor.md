# av_sync_monitor Behavior Specification

## Requirement Summary

Count audio samples per video frame, accumulate over a 256-frame measurement window, compute the average sample rate and frequency drift in ppm. Display these numbers on the engineering diagnostics page to provide concrete evidence of audio-video sync status instead of a simple checkbox.

## Public Interface

| Port | Direction | Width | Description |
|------|-----------|-------|-------------|
| `clk` | in | 1 | Pixel clock, 25 MHz |
| `rst_n` | in | 1 | Synchronous reset, active-low |
| `frame_start` | in | 1 | Single-cycle pulse at the start of each video frame |
| `aud_stb` | in | 1 | Single-cycle strobe at each audio sample (48 kHz) |
| `samples_per_frame[11:0]` | out | 12 | Average samples per frame over the measurement window |
| `fs_measured_hz[19:0]` | out | 20 | Measured audio sample rate in Hz |
| `drift_ppm[15:0]` | out | 16 | Signed frequency drift in ppm: + = audio faster than expected |

## Parameters and Defaults

| Name | Default | Description |
|------|---------|-------------|
| `FRAMES_PER_WINDOW` | 256 | Measurement window; power of 2 so division is a right-shift |
| `EXPECTED_256` | 204800 | Expected samples per 256-frame window at perfect sync (800 × 256) |

## Clocking and Reset

- **clk**: Pixel clock, 25 MHz.
- **rst_n**: Synchronous reset. Clears all counters, state machine, and result registers to initial values.
- All registers are edge-triggered; no async set/reset.

## Functional Behavior

### State Machine

Three states in `state[1:0]`:
- **S_INIT** (`2'b00`): Reset on entry. Waits for the first `frame_start` to synchronise to the video boundary. Samples are not counted during this state.
- **S_MEAS** (`2'b01`): Active measurement. Every `aud_stb` increments the per-frame counter; every `frame_start` commits that count to the running total and resets the per-frame counter. Frame index increments 0→255.
- **S_DONE** (`2'b10`): Results are computed and written to the output registers, then the module immediately returns to S_MEAS to start the next window.

### Output Computation (S_DONE)

- `samples_per_frame` = `count_total >> 8` (divide accumulated total by 256 frames). Range 0–1023.
- `fs_measured_hz` = `avg_samples_per_frame × 60`. Range 0–61380 Hz.
- `drift_ppm` = `(avg_samples_per_frame − 800) × 1250`, signed, clamped to ±32767.
  - **Derivation**: 1 frame at 60 Hz = 1/60 s. One extra sample per frame → `Δfs = 60 samples/s/frame × 1 frame = 60 Hz`. In ppm: `60 / 48000 × 10^6 = 1250 ppm`. So `1 sample/frame deviation = ±1250 ppm`.

### Result Update Rate

- One new measurement every 256 frames.
- At 60 Hz: one update every ≈ 4.27 s.
- Results are held constant until the next update.

### Accuracy

| Source | Error |
|--------|-------|
| Integer truncation of avg | ≤ ±0.5 samples/frame |
| Integer truncation of ppm | ≤ ±625 ppm |
| Total worst case | ±625 ppm ≈ ±30 Hz @ 48 kHz |

The integer-only computation is intentional: avoids a 64-bit divider and is accurate enough for diagnostic display.

## Assumptions and Chosen Defaults

- `aud_stb` and `frame_start` are both single-cycle pulses generated by `audio_sample_clk` and `video_timing` respectively. The module does not gate on the relative phase between them; it counts pulses regardless of when they arrive within each cycle.
- `aud_stb` frequency is assumed to be approximately 48 kHz. The module does not validate the frequency; it measures whatever arrives.
- The 256-frame window is chosen as a power of 2 so that division by 256 is a simple right-shift with no hardware divider.
- `drift_ppm` is signed 16-bit. Positive = audio is faster than expected (more than 800 samples/frame on average). Negative = audio is slower.

## Edge Cases and Error Handling

| Condition | Behavior |
|-----------|----------|
| `aud_stb` fires more than 1023 times in one frame | `count_frame` saturates at 12'hFFF. `samples_per_frame` will be clamped to 4095. |
| `aud_stb` fires zero times in a frame | `count_frame` = 0 for that frame; contributes nothing to total. |
| `frame_start` and `aud_stb` in same cycle | Both increments happen: frame counter resets, aud_stb increments the new frame counter. |
| Reset during MEAS | All counters cleared; state → S_INIT; partial measurement discarded without corrupting outputs. |
| Reset during DONE | Computation completes, outputs updated, then state → S_INIT. |

## Synthesis Notes (EG4S20BG256)

- **LUT4 estimate**: ~80 (FSM + 3 counters + 2 multipliers + a few muxes).
- **FF estimate**: ~50.
- **No BRAM, no DSP**.
- The multipliers are 12-bit × 6-bit and 13-bit × 12-bit, easily fitting in 2–3 LUT4s (no dedicated DSP needed at 25 MHz).
- The `>> 8` division is free (wiring).

## Verification Plan

1. **Perfect-sync inject**: In TB, assert `aud_stb` exactly 800 times per `frame_start` for 256 consecutive frames. Expect `samples_per_frame ≈ 800`, `fs_measured_hz ≈ 48000`, `drift_ppm ≈ 0`.
2. **Drift positive**: Inject 801 samples/frame for 256 frames. Expect `drift_ppm ≈ 1250`.
3. **Drift negative**: Inject 799 samples/frame for 256 frames. Expect `drift_ppm ≈ -1250`.
4. **Reset mid-measurement**: Start a measurement, fire 50 frames of data, assert reset. Verify state → INIT and no partial results.
5. **Saturation**: Inject 1500 samples/frame for 256 frames. Verify `samples_per_frame` is clamped to a reasonable max.
6. **Long-run stability**: Run for 10 full windows, verify all 10 outputs are identical for a fixed-injection scenario.
7. **Phase tolerance**: Vary the phase of `aud_stb` relative to `frame_start` (e.g., aud_stb always arrives 1 cycle before frame_start). The total per frame must still be correct.

## Acceptance Criteria

- [ ] `samples_per_frame` updates exactly once every 256 frames.
- [ ] For a fixed injection rate of N samples/frame, the measured average is within ±1 sample of N.
- [ ] `fs_measured_hz` = `samples_per_frame × 60` within integer rounding.
- [ ] `drift_ppm` = `(samples_per_frame − 800) × 1250` exactly (within integer rounding).
- [ ] Reset aborts any in-progress measurement and returns to INIT.
- [ ] All counters saturate cleanly without wrapping or corrupting state.
- [ ] No combinational paths from inputs to outputs (registered outputs only).
- [ ] `drift_ppm` is correctly signed (positive when aud_stb rate is too high).
