# audio_announcer Behavior Specification

## Requirement Summary

Orchestrate the full announcement playback sequence for a queue call event. On each `call_pulse`, parse the ticket number (BCD) and room number, then sequentially play pre-recorded PCM clips through `audio_pcm_player`: alert tone → letter → hundreds → tens → ones → "号请到" → room number → "诊室就诊". Clip locations are queried from `asset_loader` via `clip_sel → clip_base/clip_samples`.

## Public Interface

| Port | Direction | Width | Description |
|------|-----------|-------|-------------|
| `clk` | in | 1 | Pixel clock, 25.000 MHz |
| `rst_n` | in | 1 | Async reset, low-active |
| `call_pulse` | in | 1 | Trigger on new call (single-cycle) |
| `call_ticket` | in | 16 | BCD ticket number (4 digits) |
| `call_room` | in | 4 | Room number 1..4 |
| `call_prio` | in | 1 | 1=priority (P), 0=regular (A) |
| `call_recall` | in | 1 | 1=recall (no new queue entry) |
| `clip_sel` | out | 5 | Index of clip to query from asset_loader |
| `clip_base` | in | 22 | Word address from asset_loader |
| `clip_samples` | in | 22 | Sample count from asset_loader |
| `play_req` | out | 1 | Playback request to audio_pcm_player |
| `play_base` | out | 22 | Playback start address |
| `play_samples` | out | 22 | Playback sample count |
| `play_busy` | in | 1 | audio_pcm_player busy |
| `play_done` | in | 1 | audio_pcm_player done (single-cycle) |
| `announcing` | out | 1 | High during entire announcement sequence |

## Parameters

| Name | Default | Description |
|------|---------|-------------|
| `MAX_STEPS` | 12 | Maximum announcement steps (fixed at 8 + overhead) |

## Clocking and Reset

- Clock: `clk_pix` @ 25.000 MHz
- Reset: async assert / sync release, `rst_n` low-active
- All state transitions are synchronous to `clk_pix`

## Functional Behavior

### Announcement Sequence

On each `call_pulse`, the announcer plays clips in this order:

| Step | Clip Index | Content | Notes |
|-------|------------|---------|-------|
| 0 | 1 | Alert tone | Pre-recorded tone |
| 1 | 0 (regular) or 2 (priority) | 'A' or 'P' | Based on `call_prio` |
| 2 | 3 + hundreds digit | Hundreds | BCD `call_ticket[15:12]` |
| 3 | 3 + tens digit | Tens | BCD `call_ticket[11:8]` |
| 4 | 3 + ones digit | Ones | BCD `call_ticket[7:4]` |
| 5 | 13 | "号请到" | |
| 6 | 14 + (room-1) | Room 1..4 | `call_room` 1..4 |
| 7 | 18 | "诊室就诊" | |
| 8..11 | — | — | Unused (MAX_STEPS=12) |

Total: 8 clips per announcement.

### State Machine

```
S_IDLE ──(call_pulse)──► S_WAIT_BUSY ──(play_busy)──► S_WAIT_DONE
                                                              │
                    ◄──(play_done)── ◄──(step<7)── S_ADVANCE ──┘
                                                      │
                              (step>=7) ───────────────┘
                                                              │
                            ────────────────────────────────► S_FINISHED ──► S_IDLE
```

- `S_WAIT_BUSY`: issue `play_req` and wait for `audio_pcm_player` to raise `play_busy`
- `S_WAIT_DONE`: wait for `play_done` (clip finished)
- `S_ADVANCE`: increment step counter, return to `S_WAIT_BUSY`
- `S_FINISHED`: clear `announcing`, reset step counter

### Clip Lookup Protocol

1. Set `clip_sel` to desired clip index.
2. `asset_loader` returns `clip_base` (SDRAM word address) and `clip_samples` (16 kHz sample count).
3. Issue `play_req = 1`, `play_base = clip_base`, `play_samples = clip_samples`.
4. Wait for `play_busy` before clearing `play_req`.

### BCD Digit Handling

- `digit_hundreds = call_ticket[15:12]`
- `digit_tens     = call_ticket[11:8]`
- `digit_ones     = call_ticket[7:4]`
- If a digit is 4'h0 and it is the hundreds digit, it is still played (silence clip at index 3)

## Latency and Throughput

- **Per-clip latency**: 1 `clk_pix` cycle to set `clip_sel`, next cycle to get `clip_base/clip_samples`, next cycle to assert `play_req`.
- **Announcement duration**: sum of all clip durations (pre-recorded content).
- No overlap between clips; the module is a strict sequential pipeline.

## Assumptions and Chosen Defaults

- All clips fit in AUDIO_POOL; `clip_base` and `clip_samples` are always valid when `clip_sel` is set.
- Clip indices 0..31 are pre-defined in `asset_loader`. Indices not defined return base=0, samples=0, which is acceptable for the test tone slot.
- The alert tone (clip 1) could alternatively be generated by `audio_tone_gen` — the announcer outputs it as a PCM clip for simplicity.
- `call_recall` is not used in clip sequencing (same announcement for recall).

## Edge Cases and Error Handling

- `call_pulse` while `announcing == 1`: ignored (queue_fsm should not fire during announcement)
- `call_room == 0` (no room assigned): play room 1 clip as fallback
- `clip_samples == 0`: play_req is still issued; `audio_pcm_player` handles zero-length gracefully (immediate done)
- BCD digit = 0: plays clip 3 (digit 0), which is a silence recording

## Synthesis Notes

- **Resources**: counter + FSM + combinational logic, ~150 LUT4, no BRAM, no multipliers.
- Fully synchronous to `clk_pix`; no CDC needed inside.
- The `clip_for_step` function is pure combinational logic.

## Verification Plan

1. **Full sequence**: inject `call_pulse` with ticket=1234, room=2; assert clip indices match expected sequence.
2. **Prio vs regular**: assert clip 0 (A) for `call_prio=0`, clip 2 (P) for `call_prio=1`.
3. **play_busy/done protocol**: assert `play_req` is high for exactly 1 cycle per clip; `play_busy` and `play_done` are correctly sampled.
4. **Announcing flag**: assert `announcing` goes high on `call_pulse` and stays high until `S_FINISHED`.
5. **Reset**: assert `announcing=0`, `step=0`, `state=S_IDLE` after reset.

## Acceptance Criteria

- [ ] All 8 clips are played in the correct order per call.
- [ ] `play_req` is a single-cycle pulse per clip.
- [ ] `announcing` is high for the entire sequence and drops on completion.
- [ ] `call_pulse` during `announcing` is ignored.
- [ ] RTL compiles with iverilog and ModelSim with zero errors.
