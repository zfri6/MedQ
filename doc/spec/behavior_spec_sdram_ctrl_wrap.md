# sdram_ctrl_wrap Behavior Specification

## Requirement Summary

Wrapper / black-box for the SDRAM controller. The simulation branch (`ifdef SIMULATION`) provides a behavioral model that accepts requests, stores data in a simulated BRAM, and returns read data after a fixed latency — suitable for TB-level simulation. The non-simulation branch is a black-box placeholder that must be filled with the real Anlogic SDRAM controller IP generated by TD IP Generator.

## Public Interface

All ports match the `sdram_master_port` slave-side definition in `interface_contract.yaml`.

| Port | Direction | Width | Description |
|------|-----------|-------|-------------|
| `clk` | in | 1 | `clk_mem` at 100 MHz |
| `rst_n` | in | 1 | Active-low reset |
| `mem_req_valid` | in | 1 | Request valid |
| `mem_req_ready` | out| 1 | Controller accepts the request |
| `mem_req_addr` | in | 22 | Word address (32-bit word, 0..2097151) |
| `mem_req_we` | in | 1 | 1=write, 0=read |
| `mem_req_len` | in | 9 | Burst length in words (1..256) |
| `mem_wr_valid` | in | 1 | Write data valid |
| `mem_wr_data` | in | 32 | Write data |
| `mem_wr_ready` | out| 1 | Write data accepted |
| `mem_rd_valid` | in | 1 | Read data accepted by master (not used in simulation) |
| `mem_rd_ready` | out| 1 | Controller ready to accept read response |
| `mem_rd_valid_out` | out| 1 | Read data valid |
| `mem_rd_data` | out| 32 | Read data |
| `init_done` | out| 1 | SDRAM initialization complete |

## Parameters and Defaults

No parameters in the top-level module. Internal simulation model uses:
- `SIM_DEPTH=18` (262,144 words = 1 MB addressable window in simulation)
- `LATENCY=4` (read data returned 4 cycles after request)

## Clocking and Reset

- **Clock**: `clk_mem` at 100 MHz.
- **Reset**: active-low. In simulation, `init_done` is driven high after ~16 cycles.

## Simulation Branch Functional Behavior

### Initialization
- `init_done` is 0 for the first 16 clock cycles, then 1.
- The behavioral model is immediately ready after `init_done`.

### Request Acceptance
- `mem_req_ready` is 1 when the FSM is in `S_IDLE`.
- When `mem_req_valid && mem_req_ready`, the request is captured (addr, len, we).
- The FSM transitions to `S_READY` (read) or `S_WRITE` (write).

### Write Burst
- The master sends `mem_wr_valid + mem_wr_data` for `req_len` words.
- `mem_wr_ready` is 1 while the burst is in progress and the master still has data to send.
- After `req_len` words, the FSM returns to `S_IDLE`.

### Read Burst
- After request capture, a 4-cycle read latency pipeline activates.
- `mem_rd_valid_out` pulses for each word returned.
- `mem_rd_data` is the data at the addressed word (simple BRAM, address increments implicitly).

### Address Window
- Simulation uses a 1 MB window (`SIM_DEPTH=18`). Upper address bits are truncated.
- This is acceptable for simulation; real SDRAM is 8 MB.

## Non-Simulation Branch

A black-box placeholder. The actual SDRAM controller IP must be generated with TD IP Generator (APUG010 Local Bus SDRAM or APUG011 ERAM Interface SDRAM). The port names in the placeholder match `sdram_master_port`; when the real IP is available, replace the placeholder with the instantiation.

**Status**: blocked by R1 in `doc/arch/risks.md`. Does not block simulation.

## Timing, Latency, and Throughput

| Path | Latency |
|------|---------|
| `mem_req_valid` → `mem_req_ready` (idle) | 0 cycles |
| Write burst (N words) | N cycles (1 word/cycle) |
| Read burst (N words) | 4 + N cycles (4-cycle pipeline) |

## Assumptions and Chosen Defaults

- The simulation model is for functional verification only. It does not model real SDRAM timing (ACT/PRE/REF/CAS).
- The 1 MB simulation address window is sufficient for testing all protocol behaviors.
- Read latency of 4 cycles matches a typical SDRAM read latency (CAS latency ~2-3 cycles + pipeline overhead).
- The `mem_rd_valid` input is not used in the simulation model; the model always produces data and relies on `mem_rd_ready` from the slave (always 1 in simulation).

## Edge Cases and Error Handling

| Case | Behavior |
|------|----------|
| Request while controller busy | `mem_req_ready=0`; master must hold request until accepted |
| Write with `req_len=1` | Single-word write; `mem_wr_ready` pulses once |
| Read with `req_len=256` | 256 consecutive words returned with 4-cycle initial latency |
| `rst_n` pulsed during operation | FSM returns to IDLE; pending transactions aborted; `init_done` resets |
| Non-simulation branch (black box) | All outputs are tied to safe values (`1'b0` / `32'h0`); replace with real IP |

## Synthesis Notes

- **Simulation branch**: synthesizable to a simple BRAM + FSM. Resource: one BRAM (2K×32 or similar) + ~100 LUT4.
- **Non-simulation branch**: pure black box. The placeholder prevents synthesis errors; the real IP replaces it.
- **Vendor primitive policy**: vendor primitives (PLL, RAM, DDR I/O) may appear here — this is one of the two permitted files (the other is `tmds_serdes.v`).

## Verification Plan

1. **Init**: After reset, `init_done` is 0, then becomes 1.
2. **Single read**: Send a read request; confirm `mem_rd_valid_out` pulses after 4 cycles with correct data.
3. **Single write**: Send a write request followed by write data; confirm data is stored and subsequent read returns it.
4. **Burst read**: Send read request for 10 words; confirm 10 consecutive `mem_rd_valid_out` pulses.
5. **Burst write**: Send write request for 10 words; confirm all accepted and no early completion.
6. **Back-to-back**: Read-then-write; confirm second request is accepted after first completes.
7. **Non-simulation**: Confirm that the `else` branch compiles to a clean black box (all outputs tied).

## Acceptance Criteria

- [ ] Simulation branch: single read returns data after 4 cycles.
- [ ] Simulation branch: single write completes correctly.
- [ ] Simulation branch: burst read/write of arbitrary `req_len` works.
- [ ] Non-simulation branch: black-box placeholder is present and compilable.
- [ ] `init_done` is driven correctly in both branches.
- [ ] All port names match `interface_contract.yaml` exactly.
- [ ] Code is pure Verilog-2001 (vendor primitives only in `ifdef SIMULATION-`/`else` context).
