# font_rom Behavior Specification

## 1. Requirement Summary

Unified glyph ROM for OSD text rendering. Three segments packed into a single
14-bit address space (16 384 word rows × 32 bits):
- **ASCII 8×16**: 96 glyphs × 4 words/glyph = 384 rows
- **Chinese 16×16**: 128 glyphs × 8 words/glyph = 1024 rows
- **Large 32×48**: 40 glyphs × 48 words/glyph = 1920 rows

Synchronous read, 1-cycle latency. Initialized from `rtl/font_rom.hex`.

## 2. Public Interface

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| clk | in | 1 | Pixel clock 25 MHz |
| addr | in | 14 | Word row address 0..3327 (valid range) |
| dout | out | 32 | Glyph row, MSB = leftmost pixel |

## 3. Parameters and Defaults

| Parameter | Default | Description |
|-----------|---------|-------------|
| ADDR_W | 14 | Word address width (2^14 = 16 384) |
| HEXFILE | "font_rom.hex" | Initialization file path |

## 4. Clocking and Reset

- **Domain**: `clk_pix` (25.000 MHz)
- **Reset**: None required for ROM.
- **Latency**: 1 cycle (registered read).

## 5. Functional Behavior

### 5.1 Address Layout

| Segment | Glyph size | Count | Rows | Addr range |
|---------|-----------|-------|------|------------|
| ASCII | 8×16 | 96 | 384 | 0 – 383 |
| Chinese | 16×16 | 128 | 1024 | 384 – 1407 |
| Large | 32×48 | 40 | 1920 | 1408 – 3327 |

`addr` is a word-row index. For ASCII, `addr[1:0]` selects the byte within a
glyph row; `addr[9:2]` selects glyph × 4 + row. For Chinese,
`addr[2:0]` selects the byte within a glyph row; etc.

### 5.2 Data Layout

Each 32-bit word stores 4 bytes (8 pixels × 4 bits/pixel or 1 bit/pixel × 32).
The specification uses 1-bit-per-pixel packed rows (MSB = column 0 / leftmost).

- **ASCII 8×16**: each glyph is 16 rows × 8 pixels → 16 × 8 bits = 128 bits
  stored as 4 × 32-bit words. `addr[1:0]` selects which byte row within the
  16-byte block.
- **Chinese 16×16**: each glyph is 16 rows × 16 pixels → 256 bits = 8 × 32-bit words.
- **Large 32×48**: each glyph is 48 rows × 32 pixels → 1536 bits = 48 × 32-bit words.

## 6. Hex File Generation

`rtl/font_rom.hex` is generated by `tools/font_subset.py`. The script must:
1. Read glyph bitmaps for ASCII 0x20–0x7F (96 glyphs).
2. Read up to 128 Chinese glyphs (CJK Unified Ideographs subset).
3. Read up to 40 large digit/letter glyphs (0–9, A–Z, common symbols).
4. Pack each glyph into rows of 32-bit words as described above.
5. Output as big-endian hex (`%h` format) to `rtl/font_rom.hex`.

**If the hex file is empty or missing**, the ROM initializes to zero; the
OSD displays nothing. This is a valid simulation path that must not cause errors.

## 7. Assumptions and Chosen Defaults

- Hex file format: one hex word per line, big-endian, matching `$readmemh`.
- ROM size: 2^14 × 32 bits = 512 Kbit, well within EG4S20 ERAM budget
  (≈384 Kbit needed for the three segments).
- No write port; ROM is read-only after initialization.

## 8. Synthesis Notes

- **EG4 resource**: ERAM (true dual-port RAM) inferred; 14-bit address, 32-bit data.
  ≈ 512 Kbit = 50% of ERAM budget.
- **No logic** beyond address wiring.
- **Assumed IP**: None.

## 9. Verification Plan

1. **iverilog compile**: zero errors; $readmemh warning about uninitialized entries is OK.
2. **Functional TB**:
   - Read known glyph rows and compare against reference bitmaps.
   - ASCII '0' (glyph index 0x30 - 0x20 = 16): row 0 should have a specific pattern.
   - Uninitialized addresses (beyond row 3327) return zero.
3. **Tool verification**: `tools/font_subset.py` must be run to produce a valid hex.
