# 原始112条违例的修复归属

原生数据库补报每组最多500个端点；原始共91个setup、21个hold违例端点，112条最差路径全部列出。综合后网名会变化，按原始层次/数据流追踪根因；最终签核对新版整张时序图检查，而非仅检索旧网名。

| 根因组 | 原始条数 | 修复 |
|---|---:|---|
| 4条缩放器控制setup | 4 | 锁存BMP尺寸判定，拆开背压控制链；area_prior/high pack减少绕线 |
| 23条存储控制setup | 23 | FIFO可用量/行长比较分两拍，地址合法性检查从ready反馈分离；存储域实际时钟改为50MHz |
| 32条SDRAM读setup | 32 | 实际PLL输出50MHz/+8ns；保留TD的5ns输入最大延迟及全部PAD快慢角 |
| 32条SDRAM写setup | 32 | 实际PLL输出50MHz/+8ns；保留5ns输出最大延迟，并把输出min改为-1ns收紧hold |
| 19条跨时钟hold | 19 | 系统50MHz由PLL全局输出驱动；内反馈消除补偿不确定性；不切跨域路径 |
| 2条BRAM地址hold | 2 | TD原生fix_hold布线修复，最终所有同域min检查保留 |

完整原文：`baseline_full_negative.timing`；可排序逐条清单：`baseline_112_paths.csv`；含原数据库SHA256的机器记录：`path_repairs.json`。

功能侧的必要配套修复：SDRAM初始化跨越初始显示行时先显示确定的加载底色，在FIFO预充后于帧边界开始取图；仲裁为低水位显示读端保留两次请求之间的周转拍，避免持续缩放写入挤占带宽；PCM起播预充期间静音，首个样本就绪后保持原采样率/插值和运行中欠载检测。新增PCM测试同时验证“启动等待不误报”和“播放后真实缺粮必报错”。

全局setup/hold数值、原生覆盖率、I/O边界和位流SHA256见最终`summary.md`。历史报告不覆盖新版结果；旧交付包及原始失败运行均保留。
