2. 重跑真实模块综合探针，要求 optimize_rtl、optimize_gate 真正完成并产生面积报告，日志无 License/ERROR。

5. 不以退出码 0、空报告或找不到时序结果代表通过。保存命令、工具版本、源码 SHA256 和真实报告。

## 阶段 1：冻结真实板级事实

优先复用用户指出的同器件 DEMO：HX_CESHI_EG4S_BORD 的基础 IO、18_sd_card_audio 的 SD、16_uart_rs232 的 UART、31_hdmi_tx_display_B 的 HDMI/PLL。
它们可作为主链路配置的具体参考来源；先建立统一的 DEMO 基线，不要求先补齐全部原理图。
将源工程、端口重命名、引脚和电气配置逐项记录到 extracted_facts.json，再生成逐 bit 的 top.adc。
原理图/权威引脚表用于解决不同示例之间的具体冲突，以及没有示例覆盖的功能；复用核对见 `demo_reuse_matrix.md`。
第二 HDMI 先确认方向、电路和差分对；Flash 先确认芯片型号、用户数据接口以及与配置 Flash 的关系。

通过标准：主链路每个顶层端口均有真实引脚与电气来源；无自动分配、无 virtualIO 占位端口进入可下载位流。

## 阶段 2：把行为模型边界换成真实硬件

### 时钟和复位

用 TD IP Generator 生成并保存 wrapper + ipc。输出为 25 MHz 像素、125 MHz 串化、100 MHz 存储；50 MHz 系统使用板载时钟。
优先评估单 PLL 的合法三输出配置；若使用两个 PLL，两者的锁定均参与复位释放。
不要直接修改现有冻结的厂商文件；新生成版本单独留档并调整例化。

### SDRAM

取得 APUG010/APUG011 或 lab_ex_4 的控制器与时序资料，适配到既有 32-bit、字地址、1..256 字的 valid/ready 突发接口。
实现上电初始化、模式设置、行/列/Bank 地址映射、刷新、读写方向切换和读延迟。
控制器不能被下游反压直接暂停物理 SDRAM 数据拍，必要的缓冲需在适配层吸收。
把真实控制器与厂商模型接入 ModelSim，覆盖初始化、刷新、跨行/Bank、全地址区间、交错读写及反压。

### HDMI 串化

基于已确认的 EG4 DDR 输出原语或厂商串化模块，真正每像素输出 10 bit；确认两边沿、LSB-first、通道相位和复位首字。
保持时钟 lane 和三个数据 lane 的相位关系。使用真实原语模型复跑串化与 HDMI 协议自检。
不以当前 SIMULATION 分支的行为串行器代替真实硬件分支验收。

### BRAM / FIFO 与素材

确认字体 ROM 的 HEX 初始化进入实际工程；验证 ROM 延迟和像素对齐。
重点检查异步 FIFO、字模、两行缩放缓冲、OSD 字符存储的 RAM 推断。若改为厂商 FIFO/BRAM，补齐首字有效和读延迟适配后复跑回归。
当前异步 FIFO 使用异步读，不能预先保证 TD 会将它映射为预期的块 RAM；实际资源以综合报告为准。

真实 SD 卡需使用支持的 FAT32/MBR 或 superfloppy 布局，BMP 无压缩，PCM 为 16 kHz/16-bit/有符号/单声道原始样本。
测试中的 HEX 是缩小的合成文件系统，不是可直接烧写的真实卡镜像。
当前 PCM 索引来自 FAT 目录枚举顺序（fat32_reader -> asset_loader），不是按文件名排序；实卡目录重排可能导致片段与数字对应错误。
上板前应改为明确文件名/清单到 clip_id 的映射，并用真实大小、打乱目录顺序的 FAT32 图像验证。

## 阶段 3：TD 全工程综合、实现、生成位流

工程名称使用 MedQ，源为本项目 rtl；参考 DEMO 只作为 IP/约束和工具流程证据。
不要定义 SIMULATION，不加入 tb 或 sim_anlogic_stubs；不要用 top_skeleton 替代实际 top。
使用 ASCII 镜像路径，例如 C:/anlogic_work/MedQ，保留可追溯的源码与初始化文件清单。

1. 综合通过：无未绑定模块、无空硬件分支、无不期望 latch/多驱动；报告 LUT、FF、各类 BRAM、DSP、PLL。
2. 确认 SDRAM、读取器、加载器和音频链路没有因为常量 init_done/ready 等占位信号被优化掉。占位顶层综合成功也不能算有效。
3. SDC 对板载输入及真实 PLL 输出建立准确关系；特别保留 25/125 MHz 的串化时序关系。
   CDC 例外只施加在有依据的同步路径，不用全局 false path 掩盖跨域或时序失败。
4. 布局布线后读取 setup、hold、恢复/移除、时钟利用与例外报告；无未解释的负 slack 或未约束工作时钟。
5. 输出 MedQ.bit、完整资源/时序报告、source manifest、bit SHA256。必须是本次源码生成的位流，不能拿示例 bitstream 代替。

## 阶段 4：首次实板验证，先下载 SRAM

接好板卡电源、下载器、HDMI 显示器、准备好的 TF 卡；如需终端调试再接 UART。
按板卡手册设置启动/下载方式。TD 下载工具识别器件链后，选择本次 SHA256 对应的 MedQ.bit，先做 SRAM 下载。
具体菜单和 Flash 选项以当前 TD 下载器/板卡手册为准，不能在还未识别目标存储器时擦写 Flash。

分层验证，上一层失败就先定位本层，不同时叠加多个未测功能：

| 顺序 | 激励/观察 | 通过标准 |
|---|---|---|
| 1 | 上电、PLL lock、LED/UART | 复位可靠释放；真实频率、板卡极性及 UART 通信正常 |
| 2 | 片上产生图案和新版 OSD | 单屏连续输出、字符清晰、无错行/闪屏；不依赖 SD 读取成功 |
| 3 | SDRAM 独立自检 | 地址线/数据模式/边界/刷新/突发读写 CRC 正确 |
| 4 | TF 真实 BMP/PCM 装载 | 正确识别文件及片段，数据 CRC 与 PC 参考一致 |
| 5 | 按键取号、下一号、重呼、UART CRC | 屏幕、数码管、诊室、语音和队列状态一致；重呼不消耗下一票 |
| 6 | 长时运行、重复上电、无卡/坏素材 | 不欠载、不卡死；错误可见且能按设计恢复 |

可为以上层次分别提供带源码/bit 哈希的 bring-up 工程配置；最终验收仍需完整 MedQ 同一位流运行主链路。
记录下载工具原始结果、位流 SHA256、实板照片/视频、UART 日志与必要测量数据。
确认 SRAM 下载和主链路稳定后，才按配置 Flash 的具体型号、地址和启动设置固化；断电再上电验证自动启动。

## 阶段 5：扩展逐项加入

### 用户数据 Flash 持久化

先读 JEDEC ID，确定指令/地址模式、容量、擦除粒度和预留扇区，确保与 FPGA 配置区隔离。
补齐顶层引脚和启动 load_req，再做双槽记录、序号/CRC/提交标记、忙轮询与有限超时。
当前快照只保存当前/下张票和部分状态，未保存 RAM 中全部候诊队列；若要求掉电保留全队列，需先扩展持久化格式与恢复策略。
断电测试覆盖擦除、写入、提交中断，不允许恢复为半条新记录或倒退票号。

### 第二屏

确认接口可输出后，先做同源镜像，检查新增输出管脚、时钟、串化与资源；再做独立导诊视图。
同源双视图优先共享时序和可共享的数据，避免无必要的第二路 SDRAM 读取；不同画面时重新评估带宽和缓冲。
双屏同时显示并播放时仍无视频/音频欠载、无时序失败，才算扩展通过。

### 完整诊断

先修正 av_sync_monitor 中 60 Hz/每帧 800 样本的假设：本工程 25 MHz/800/525 = 59.5238 Hz，48 kHz 对应平均 806.4 样本/帧。
诊断页接入真实 SD/FAT/载入状态、PLL lock、SDRAM 自检、显示/音频欠载计数、CRC、版本和构建 ID。
对时钟、延迟和音视频指标区分计算值、FPGA 内部测量和外部仪器测量。
用真实故障注入验证告警，而不是仅将计数器或“正常”字样画到页面上。
