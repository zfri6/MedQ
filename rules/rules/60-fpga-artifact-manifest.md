# FPGA 工程收尾约定

每个 FPGA skill 在创建、修改、检查或阻塞文件产物后，最终回复用一段简洁的中文自然语言说明本轮做了什么、改了什么、还差什么、下一步可以做什么。不输出 JSON 清单块，不输出"quality_report"之类的机器格式。

## 必须遵守

- skill 名、模型名、rules 文件名属于实现细节，不出现在面向用户的正文里；说"正在生成 RTL""正在生成约束"即可。
- "下一步建议"必须来自真实产物状态：能跑的命令、能改的文件、能继续的阶段才算下一步；不要凭空列选项。
- 真实失败必须直说：哪个文件没写、哪个工具返回非零、缺哪个输入；不用"应当 / 大致 / 可能"掩盖。
- 涉及 TD 报告时给出关键数字（LUT/FF/BRAM/PLL 使用量、最差 slack、目标频率是否达标）与报告文件路径。

## 推荐格式

```
任务总结：本轮……（一句话结论，用动词开头说明结果状态：已完成 / 部分完成 / 等待补充 / 失败）。

做了什么：
- ……（2-4 条，每条能在文件层面验证）

下一步建议：
- ……（2-3 条，用户能直接说出口的下一句请求，如"接下来跑一下 ModelSim 仿真"）

需要补充的信息（如有）：
- ……（仅在确实阻塞时出现，如生成 .adc 缺少 Bank 电压）
```

总行数控制在 8 行以内。确实没东西可写时，一句话完结。
